# 时间轴阶段（Phase）显示 / 跳转 / 编辑设计

## 1. 背景与目的

长战斗（如绝境战，常见 15～20 分钟）里，用户现在只能在时间轴上一屏屏翻，靠认 boss 标志性技能来判断「现在是哪个阶段」。FFLogs 报告本身带有阶段切换数据（`fights.phaseTransitions` + `report.phases`），可以直接利用。

本功能让编辑器里**看得到每个阶段从哪开始、能一步跳过去、能手动改**。阶段只是时间上的**标记**，不承担任何计算语义：移动、增删阶段都不会影响伤害事件、技能或减伤计算。

适用范围：FFLogs 导入、副本模板新建、空白新建三种来源的时间轴都要能显示和编辑阶段。

## 2. 目标 / 非目标 / 反目标

**目标**

- 主时间轴、缩略图、表格视图都能显示阶段边界。
- 工具栏提供阶段跳转入口，显示「当前所在阶段」。
- 阶段可手动添加、改名、改时间、删除；协作同步、可撤销。
- FFLogs 导入与副本模板自动带入阶段；阶段名可通过 Crowdin 维护的对照表翻译。

**非目标（本次不做）**

- 副本名接入 i18n（用户明确延后，以后单独做）。
- 给已存在的 FFLogs 导入时间轴补充阶段（只有新导入的才带）。
- 表格视图「两行之间悬停出现 ＋」的添加入口（用户明确目前不加）。
- Souma 导出、Excel 导出、复制粘贴（`timelineClipboard`）里携带阶段。【我的决定，见 §12】
- 编辑器内「导入到当前时间轴」（`ImportIntoTimelineDialog`）带入阶段：该入口不涉及阶段，保持现状。（用户决定）

**反目标（做了反而算失败）**

- 拖动 / 修改阶段时连带移动伤害事件或技能。阶段线**只挪自己**。
- 为阶段新增属性面板（PropertyPanel）。用户明确不希望再给其他实体加属性面板。
- 自动给阶段编号、自动改写其他阶段名。阶段名是自由文本，可能是 `P4.5`、`转场`、`Intermission: Limit Cut`。

## 3. 已核实的 FFLogs 数据形态

用项目 `.dev.vars` 的 client credentials 调 v2 GraphQL 实测（2026-10-19 / 20）：

```graphql
report(code) {
  fights(fightIDs: [...]) { startTime phaseTransitions { id startTime } }
  phases { encounterID separatesWipes phases { id name isIntermission } }
}
```

- `phaseTransitions[].startTime` 与事件时间戳同基准（报告相对毫秒）。
- `phases` 按 encounter 给出 id → 名称、是否转场；名称**只有英文**。
- 实测样本：

| 副本                            | 阶段名示例                                          | 备注                                                                        |
| ------------------------------- | --------------------------------------------------- | --------------------------------------------------------------------------- |
| DMU 1085                        | `P1: Kefka` … `P5: Ultima Kefka`                    | 报告 `nQFXVpAH2cWkd8RZ#12`，P2 3:29.2 / P3 7:09.0 / P4 12:19.0 / P5 15:03.1 |
| TEA 1075                        | `Intermission: Limit Cut`（`isIntermission: true`） | 有转场                                                                      |
| DSR 1076                        | `Intermission: Rewind!`                             | 该样本 P1、P2 的 transition 时间**相同**（都在 0.0）                        |
| UWU 1074                        | `Garuda`、`Ifrit`                                   | **没有** `P?:` 前缀                                                         |
| FRU 1079 / TOP 1077 / UCoB 1073 | `P1: …` 格式                                        |                                                                             |

## 4. 数据模型

### 4.1 Timeline

```ts
/** 时间轴阶段标记（纯展示 / 导航用，不参与计算） */
interface TimelinePhase {
  id: string
  /** 自由文本，完整显示名，如 "P3: Exdeath and Chaos"、"P4.5"、"转场" */
  name: string
  /** 开始时间（秒），与 DamageEvent.time 同口径（相对 resolveFightStartTime 零点，可为负） */
  time: number
}

interface Timeline {
  // …
  phases?: TimelinePhase[] // 存量时间轴无此字段 = 无阶段
}
```

- 阶段**没有**单独的序号字段；P1、P2 等完全由 `name` 文本承载。
- **颜色、顺序**都不存储：按 `time` 排序后的位置推导（见 §6.1）。

### 4.2 持久化与协作（需同步改动的位置）

- V2 持久化格式（`src/types/timelineV2.ts` / `src/utils/timelineFormat.ts`）：新增可选字段（如 `ph`），缺席 = 无阶段；V1 迁移不产生阶段。
- Yjs 文档（`src/collab/docSchema.ts`、`constants.ts`）：新增一个按 `id` 为 key 的 `Y.Map`（同 `annotations` 的做法，便于并发编辑单个阶段），提供 add / update / remove 与 `projectTimeline` 投影。
- `SyncEngine` 的 `UndoManager` 跟踪列表加入该 map，使阶段的增删改可撤销 / 重做。
- 其他与 `annotations` 同路径的地方（`timelineToLocalInit`、`migration`、`timelineStorage`、`internalMigrate` 等）按需带上该字段；具体列表由实施者以 `annotations` / `syncEvents` 的引用点为线索核对。

### 4.3 副本模板（EncounterTemplate，KV）

模板新增可选字段，存**未翻译的 FFLogs 原始数据**，翻译推迟到「用模板建时间轴」那一刻：

```ts
phases?: { fflogsPhaseId: number; name: string /* FFLogs 原文 */; time: number /* 秒 */ }[]
```

- 来源：`top100Sync` 采样时，阶段数据与本场伤害事件来自**同一场战斗**，并用同一个 `resolveFightStartTime` 零点换算。
- 写入时机：跟随现有的模板覆盖策略（`shouldReplaceTemplate`：kill 优先、时长更长才覆盖），阶段与事件一起整体替换，保证两者同源对齐。
- 新写入的模板**总是带 `phases` 字段**：FFLogs 没有阶段数据时写空数组 `[]`。因此「字段缺席」只表示存量模板，「`[]`」表示确认无阶段。
- 存量模板补齐（用户决定）：`shouldReplaceTemplate` 新增一条——旧模板为 kill 且**缺 `phases` 字段**时，新 kill 无论时长都覆盖。下一次采样到 kill 即自动补上阶段。该规则不作用于 wipe 模板（避免较短的 wipe 顶掉较长的 wipe）；`phases: []` 的模板不触发（避免单阶段副本每次都被覆盖）。

## 5. 导入与翻译

### 5.1 FFLogs 导入（`/api/fflogs/import`）

1. `getReport` 的 GraphQL 查询追加 `fights.phaseTransitions { id startTime }` 与 `report.phases { encounterID phases { id name isIntermission } }`。
2. 对选中 fight：取 `phases` 中 `encounterID === fight.encounterID` 的那组名称表，把每个 transition 映射为 `{ fflogsPhaseId, rawName, time }`，其中 `time = (startTime - fightStartTime) / 1000`，`fightStartTime` 与伤害事件用同一个 `resolveFightStartTime`。
3. **同一时刻多个阶段**（如 DSR 样本 P1/P2 同为 0.0）：时间相同（差 < 1 秒）的只保留**最后一个**（较晚出现的才是实际生效的阶段）。【我的决定】
4. 第一阶段时间若早于时间轴起点 `TIMELINE_START_TIME`（-30s），钳到起点；否则保留原值（可能是小负数）。【我的决定】
5. 名称按 §5.3 翻译后写入 `timeline.phases`。
6. 没有阶段数据（单阶段副本或 FFLogs 未收录）→ 不写 `phases` 字段。

### 5.2 副本模板新建

用模板建时间轴（`CreateTimelineDialog` / `useEncounterTemplate` 路径）时，把模板里的 `phases` 按 §5.3 翻译成 `TimelinePhase[]`，生成新 `id`。

### 5.3 阶段名翻译（导入时翻译）

用户决定：**导入时翻译**——在导入 / 建轴那一刻按导入者当前语言查表，结果作为普通文本存入时间轴；之后不随查看者语言变化。

- 对照表放在 i18n 资源里，由 Crowdin 维护（源语言 zh-CN，翻译到 zh-TW / ja / en / de / fr / ko-KR 等现有语言）。
- key **必须带统一前缀**（用户要求）。我的提议：新增命名空间 `encounter`，key 为 `phase.e{encounterId}.p{fflogsPhaseId}`，如 `encounter:phase.e1085.p3` →（zh-CN）`P3：艾克斯迪司与卡奥斯`。前缀格式待用户在 review 时确认。
- **查不到 key、或值为空串 → 保留 FFLogs 原文**（i18next-parser 配置的 `defaultValue: ''` 会产生空串，必须当作缺失处理）。
- key 是动态拼出来的，不会被 i18next-parser 抽取；现有配置 `keepRemoved: true` 可保证手写的 key 不被删掉。
- 翻译发生的位置（Worker 用请求的 `lang` 查，还是前端用 i18next 查）留给实施者；要求两条路径（导入、模板新建）结果一致，建议抽一个共享纯函数。注意前端 locale 是懒加载的，Worker 侧直接 import JSON 要关注 bundle 体积。
- 本次只需建立机制和空表；具体中文译名由维护者在 zh-CN 源文件里逐步补充（游戏内名称需按 `AGENTS.md` 的数据源规则核实，不可凭记忆填写）。

## 6. 显示

### 6.1 配色

- 7 色循环：**灰、绿、蓝、紫、橙、粉、金**（原型取值 `#6b7280 #22c55e #3b82f6 #a855f7 #f97316 #ec4899 #ca8a04`），按排序后的位置分配，第 8 个回到灰。
- 插入 / 删除阶段时，后续阶段颜色顺延——用户已确认这样可以。
- 与现有语义色（绿=持续时间条/HP，蓝=CD 条/视口，橙金=缩略图伤害柱）可能撞色，用户认为渐变段短、可接受。
- 文字色用该色加深（原型：`color-mix(var(--pc) 72%, #000)`）保证对比度；深色模式下实施者适当提高渐变不透明度。

### 6.2 主时间轴（Konva）

- 阶段开始处一条 2px 竖线，向右一段**固定 200px 宽**、从该色到透明的线性渐变，贯穿标尺、HP 曲线、伤害轨与所有技能轨。宽度不随阶段长度、缩放变化。
  - 注意：固定区（标尺 / HP / 伤害轨）与技能轨是两个独立 Stage，两边都要画；遵守 Layer ≤ 3、关闭阴影 / perfectDraw 的性能约定。
- 阶段名：标尺上（标尺高 30px，刻度每 10 秒、文字 12px）、竖线右侧的无底色彩色粗体文字。
- **与刻度冲突**：与阶段名（或选中标签）水平区间重叠的刻度，**文字和刻度线一起隐藏**。
- **悬停**：淡底色 + 左右拖动光标；停留约 0.45s 弹出提示「拖动调整时间 · 双击重命名 · 右键更多」。
- **选中**（单击）：变成该色实底标签「名称　开始时间（mm:ss.f）　✎　🗑」。标签上悬停提示「拖动调整开始时间」；✎ / 🗑 各自 tooltip「重命名（双击）」「删除（Del）」。标签变宽后被挡住的刻度同样隐藏。点空白处取消选中。

### 6.3 缩略图（TimelineMinimap）

- 每个阶段起点画一段**固定 64px 宽、铺满缩略图整个高度**的渐变，左上角写**短标签**。
- 短标签规则：名称里有冒号（`:` 或 `：`）取冒号前部分（`P3: Exdeath and Chaos` → `P3`）；否则取前 6 个字符，超出加省略号（`Garuda` → `Garuda`）。
- 缩略图**只显示**阶段，不做阶段跳转：按下 / 拖动仍沿用现有「以点击位置为中心定位视口」的行为。阶段跳转统一走工具栏下拉菜单。（用户决定；原型里「点击跳到阶段起点」的行为不采用）

### 6.4 工具栏跳转入口（EditorToolbar）

- 位于工具栏**最右端**，不参与横向滚动；左侧按钮区单独横向滚动。
- 按钮区放不下时，按钮区右边缘出现 **96px** 的白色渐隐（从透明到背景色）；滑到最右端时渐隐消失。**不画分隔竖线**。
- 入口文字随工具栏宽度三档变化（原型阈值，实施者可微调）：≥900px「完整名称 + 开始时间 mm:ss ▾」；≥520px「短标签 + 时间 ▾」；更窄「短标签 ▾」。
- 入口边框 / 文字跟随**当前所在阶段**的颜色。视口在第一个阶段之前时显示「开场前」（中性灰）。
- **当前所在阶段**：时间轴视图取「视口左缘 + 40px」对应的时间；表格视图取表头下方第一条可见行的时间。取开始时间 ≤ 该时间的最后一个阶段。
- 下拉菜单：每项「色块 + 名称 …… 开始时间」，当前阶段高亮。悬停某一项时，**右侧的时间被 ✎ / 🗑 顶替**（固定宽度，不跳动）；✎ 在菜单内原地改名（Enter 确认、Esc 取消）。分隔线下方为「＋ 在当前位置添加阶段　mm:ss」，颜色与普通菜单项一致（不用强调色）。
- 选择某一阶段 → 平滑滚动，使阶段起点位于视口左缘偏右 40px（留一小段前一阶段内容）；表格视图滚到该阶段行贴住表头。
- 时间轴**没有任何阶段**时：入口显示为虚线边框的「＋ 阶段」，点击即在当前视口位置添加一个阶段；只读时显示「无阶段」。

### 6.5 表格视图（TimelineTable）

- 每个阶段在其开始时间处插入一条**阶段分隔行**（高 30px），时间列显示开始时间（mm:ss.f），其后是阶段名。
- **吸顶**：当前阶段的分隔行 sticky 在表头下方；滚到下一阶段时被新的阶段行顶替。
- 背景：从时间列开始、该色渐变到透明，**一直铺到表格最右侧**；阶段名像备注行一样 sticky 在可视区左侧；吸顶 / sticky 单元格垫实底，避免下方内容透出。
- 边线：阶段行的上下边缘都用该色的浅色（上边缘即上一行的下边线，需一起改色）。
- 悬停：时间上出现描边 + 虚线下划线 + 提示「单击修改开始时间」；名称上出现淡底色 + 提示「双击重命名 · 右键更多」；悬停整行时名称后露出 ✎ / 🗑。

## 7. 编辑交互

| 操作   | 时间轴视图                                       | 表格视图                                                        | 下拉菜单                                           |
| ------ | ------------------------------------------------ | --------------------------------------------------------------- | -------------------------------------------------- |
| 添加   | 标尺 / 轨道空白处右键「在此处添加阶段　mm:ss.f」 | 伤害事件行右键「在此行前添加阶段」                              | 「＋ 在当前位置添加阶段」；无阶段时入口「＋ 阶段」 |
| 改名   | 双击阶段名；选中标签 ✎；右键「重命名　双击」     | 双击名称；行尾 ✎；右键「重命名　双击名称」                      | 悬停 ✎，原地编辑                                   |
| 改时间 | 拖动阶段名 / 选中标签                            | 单击时间直接输入（如 `7:12.5`）；右键「修改开始时间　单击时间」 | —                                                  |
| 删除   | 选中标签 🗑；右键「删除阶段　Del」；选中后 `Del` | 行尾 🗑；右键「删除阶段」                                       | 悬停 🗑                                            |

规则：

- **新增阶段默认名**：按插入位置预填 `P{n}`（n = 插入后的序号），并立即进入改名状态；其他阶段名字**不变**。
- **时间约束**：不能越过相邻阶段，与相邻阶段至少相隔 1 秒；输入越界时钳到允许范围并提示。下限为 `TIMELINE_START_TIME`。
- **改名**：Enter 确认、Esc 取消、失焦确认；清空名字视为取消。
- **删除确认**：所有删除途径（含 `Del` 键、右键菜单）都先弹出确认 Popover，样式沿用 `src/components/FilterMenu/SortablePresetRow.tsx`：标题「确认删除？」+ 灰色小字阶段名 + 「取消」（outline）/「删除」（destructive）；锚定在触发元素下方、右对齐；焦点默认在「删除」，Enter 确认、Esc 或点外部取消。从下拉菜单删除后菜单保持展开。
- **权限**：阶段属于 `content` 能力。只读（view 模式、离线、手动锁、回放模式）时只能看和跳转：不显示悬停底色 / 提示 / ✎🗑，不能拖动、添加、删除。注意 FFLogs 导入的时间轴默认处于回放模式，需退出回放后才能编辑阶段。
- 所有编辑走 Yjs 事务，可撤销 / 重做，并实时同步给协作者。一次拖动（按下到松开）只算一步撤销。
- **选中互斥**：选中阶段会清空伤害事件 / 技能 / 框选的选中；反之亦然。框选不包含阶段。`Del` 在选中阶段时只作用于阶段（走确认框），不影响原有对事件的删除行为。
- **右键菜单整合**：时间轴空白处的「在此处添加阶段」作为一项加入现有 `TimelineContextMenu`（与「添加」「添加备注」并列），不另起菜单。
- **名称长度**：上限 50 字符（与时间轴名称上限 `TIMELINE_NAME_MAX_LENGTH` 相同，新常量放 `src/constants/limits.ts`）。【我的决定】
- **表格排序**：阶段行排在开始时间 ≥ 该阶段时间的第一条事件 / 备注行之前（同一时刻时阶段行在前）。

## 8. 操作可发现性

用户不希望用属性面板。采用的组合（均已在原型验证）：

1. 悬停时的视觉暗示（淡底色、拖动 / 文本光标）+ 延迟 tooltip 说明快捷方式。
2. 选中后实底标签内直接带 ✎ / 🗑。
3. 右键菜单右侧标注快捷方式（双击 / Del / 单击时间）。
4. 下拉菜单悬停露出 ✎ / 🗑。
5. 公开文档：在 `docs/howto/` 新增阶段用法说明，并在 `docs/tutorial.md` 补充相关内容（遵守 `docs/` 路径与本机信息检查规则）。

## 9. i18n 文案

所有新增 UI 文案（入口、菜单项、tooltip、确认框、「开场前」「无阶段」等）走现有命名空间（`editor` 为主），zh-CN 手写，经 Crowdin 翻译。阶段名对照表见 §5.3。

## 10. 测试要点

- 导入解析：transition → 相对时间换算（同 `resolveFightStartTime` 零点）、同时刻去重、无阶段、名称表按 encounter 匹配、翻译命中 / 未命中 / 空串回退原文。
- V2 序列化往返、缺席字段兼容存量数据；Yjs 投影、并发编辑、UndoManager 覆盖。
- 模板：阶段随模板整体替换；无阶段写 `[]`；旧 kill 模板缺 `phases` 时被任意新 kill 覆盖，`[]` 与 wipe 模板不受影响；建轴时翻译并生成 id。
